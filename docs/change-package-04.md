## Мета й обмеження

Створити інфраструктуру валідації **майбутньої** експертної розмітки тверджень та порівняння вердиктів системи з еталоном. Наразі в репозиторії є лише `data/eval_queries.json` з 20 початковими запитами, але немає підтвердженого незалежного експертного набору тверджень. **Не оголошувати** синтетичні unit-тести результатами магістерських експериментів.

## План змін перед внесенням коду

1. `src/modules/evaluation/benchmark.gold.ts` — декларативні типи та строгий валідатор структури gold-датасету: ідентифікатори, train/dev/test split (лише dev/test для початкової експертної перевірки), еталонні вердикти, зв'язок доказу з текстом джерела, метадані версії корпусу, анотації та незалежного погодження.
2. `src/modules/evaluation/benchmark.metrics.ts` — обчислення confusion matrix, per-class precision/recall/F1, macro-F1, accuracy. Невідомі, дубльовані або відсутні пари caseId/claimId повинні викликати помилку, а не тихо виключатися зі статистики.
3. `src/modules/evaluation/benchmark.cli.ts` — CLI `benchmark:validate <gold.json>` для офлайнової перевірки, без Ollama/ChromaDB.
4. `src/tests/benchmark.checks.ts` — unit-тести на синтетичних даних для позитивних сценаріїв, підробленого доказу, некоректних вердиктів, неповних прогнозів, контрольних розрахунків метрик.
5. `data/benchmark/README.md` та `docs/benchmark-annotation-protocol.md` — правила створення реального датасету та різниця між розміченими даними, тестовими прикладами й експериментальними висновками.
6. `package.json` і `.github/workflows/ci.yml` — підключити офлайн-тести до CI (без запуску повного RAG).

## Критерії приймання

- Не існує жодного внесеного «еталонного» документа або вердикту без реальної розмітки.
- Валідація відхиляє невідомі вердикти, дублікати ідентифікаторів, відсутні тексти, підроблені цитати та недопустимі split.
- Дані мають стабільний ідентифікатор знімка корпусу та вказують джерело, версію документа й ідентифікатор доказового фрагмента.
- Для `supported` і `contradicted` потрібна фактична доказова цитата з реального переданого фрагмента.
- Офлайнове порівняння не ігнорує пропущені або зайві прогнозовані твердження.
- Unit-тести проходять в CI, але це не вважається доказом емпіричної ефективності.
- Порівняння методів на еталонному наборі буде наступним окремим пакетом, коли дані існуватимуть.

## Ризики / наступні рішення

- Валідація підрядка цитати не доводить семантичного entailment. Висновки експертів обов'язково перевіряються незалежно.
- Декомпозиція LLM-відповідей на твердження може відрізнятися від розмітки. Прогнозний файл для цього пакета має явно надавати ID еталонного твердження; алгоритм зіставлення довільних тверджень — окреме наукове завдання.
- ТЗ ще не затверджено остаточно; це інфраструктурний крок, що не змінює формулу Trust Score.
