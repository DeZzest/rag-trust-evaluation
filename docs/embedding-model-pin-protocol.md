# Мінімальна прив'язка embedding-моделі до ChromaDB snapshot (пакет 16)

## Для чого

Індексування з пакета 13 створювало окрему колекцію `rag_snapshot_<sha256>` без збереження моделі, яка побудувала вектори. Якщо змінити `EMBEDDING_MODEL` і залишити стару ChromaDB, нові запити можуть шукати в несумісному векторному просторі.

Пакет 16 використовує модель, уже вказану в `EMBEDDING_MODEL`, і фіксує її **декларований тег** у Chroma metadata разом із `corpusSnapshotId`, типом Ollama API `/api/embeddings`, cosine distance і SHA-256 **конфігурації**. Це не верифікація фактичного digest ваг моделі.

## Дії під час індексації

```env
EMBEDDING_MODEL=nomic-embed-text
```

Назва — лише приклад; обрати конкретний tag заздалегідь і більше не змінювати між індексацією та RAG-прогонами. Після перевірки corpus snapshot запустити окремий індексатор з `--execute` (див. `docs/snapshot-chroma-index-protocol.md`). Під час **нового** create-only створення Chroma отримує metadata:

```text
hnsw:space                  = cosine
rag:snapshot_id             = sha256:<corpus-id>
rag:embedding_model         = <exact EMBEDDING_MODEL tag>
rag:embedding_api           = ollama:/api/embeddings
rag:embedding_config_sha256 = SHA-256 від переліку параметрів вище
```

При відкритті snapshot-колекції для read-only RAG-запиту чи перевірки індексу наявність цих полів перевіряється. Якщо колекція позначена іншою моделлю або не має metadata, буде **відмова без fallback**. Порядок і конфігурація користувача беруться із серверного середовища, а не з HTTP body.

## Межі

- Перевірка metadata запобігає **випадковій** плутанині модельних тегів, але не є криптографічним доказом того, що Ollama реально використовувала саме ці ваги.
- Колекції, створені до пакета 16 без цих metadata, новий endpoint свідомо відхиляє. Не слід редагувати їх автоматично або перепризначати model tag без перевірки; потрібен окремо погоджений новий дослідницький запуск.
- Назва колекції все ще залежить лише від snapshot ID, тому **один snapshot — один експериментальний embedding tag у такій колекції**. Для мінімальної магістерської реалізації цього достатньо. Мультимодельні прогони індексації не входять до обсягу.
- Для відтворюваності локально зберегти stdout `ollama list`, `ollama show <EMBEDDING_MODEL>`, `ollama --version`, версію ChromaDB та файли конфігурації експерименту; не зберігати паролі чи токени.
- Після успішного CI необхідно перевірити **реальну** форму Chroma v2 collection metadata при локальному запуску. Синтетичні тести не підміняють інтеграційної перевірки.

## Тести

```bash
npm run test:embedding-pin
```

Це офлайнова перевірка стабільності конфігураційного SHA-256 і блокування невідповідностей тегу, snapshot ID, cosine space та відсутніх metadata. Вона не вимагає Ollama/ChromaDB й не вимірює достовірність відповідей.
