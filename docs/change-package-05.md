# Пакет 5 — відтворюване формування черги експертної розмітки

**Дата:** 2026-11-18  
**Базовий commit:** `30a20a52790b87f5f86bff0ad8bb0e8208f5a239` (PR #18, main)  
**Гілка:** `feat/benchmark-annotation-queue`  
**Стан:** робочий план змін; остаточне ТЗ ще потребує погодження.

## Підстава

`data/eval_queries.json` містить 20 початкових запитів з ідентифікаторами передбачуваних документів, однак не експертно перевірені атомарні твердження. Реальний корпус і результат інжесту (`data/university_corpus/`, `data/ingested_corpus.jsonl`) ігноруються Git; у репозиторії їх не виявлено. Тому **не можна** придумувати реальні цитати, мітки або нібито перевірений gold dataset.

## План реалізації

1. Додати чисту функцію формування **незавершеної черги на розмітку** з вмісту `data/ingested_corpus.jsonl` та `data/eval_queries.json`. Збереження вихідної послідовності кандидатних чанків, чітке зіставлення `documentId + year` з очікуваними документами, позначення випадків, для яких джерело не знайдене.
2. Зафіксувати хеші SHA-256 **точних вхідних файлів**, ідентифікатор знімка корпусу, document ID/рік/секцію/первинний текст; сформувати стійкий ID фрагмента. Усі записи — зі статусом `needs_manual_annotation`. Жодного автоматичного поля `verdict` або `groundTruth`.
3. Додати `npm run benchmark:prepare -- <ingested.jsonl> <eval_queries.json> <output.json>`; зупинка з помилкою при відсутності вхідних файлів, пошкодженому JSON, відсутніх метаданих, конфліктних id або спробі використати файл результату як вхід.
4. Зберігати генерацію в `data/benchmark/annotation-queue*.json` (Git-ignored за замовчуванням) для захисту документів та експертних даних від випадкового коміту.
5. Розширити синтетичні unit-тести — matching документів і року, відсутні джерела, стабільність хешів, незмінність вхідних даних, виявлення пошкодженого JSON.
6. Доповнити протокол розмітки: черга — лише кандидатні фрагменти, не gold; необхідні незалежні експертні оцінки та контрольні сценарії суперечностей, відмови від відповіді, чинності редакцій.
7. CI має виконувати offline-тести й TypeScript typecheck без доступу до живих сервісів.

## Критерії приймання

- Черга створюється лише з наданих файлів; не запускає LLM і не генерує фактів.
- Для кожного з вхідних запитів є case ID та статус; відсутні джерела видно явно.
- Контроль версій не зливає документи різних років.
- Хеші та ID однакові для незмінних вхідних файлів, зміна вхідного файлу змінює хеш snapshot.
- Дані черги відокремлені від формату експертного gold і не можуть випадково пройти `benchmark:validate`.
- Нові unit-тести й CI зелені; результати на справжніх університетських файлах не заявляються до фактичного запуску.

## Межі

Даний пакет готує *чергу для ручної роботи*, а не автоматичну істину; без доступу до локального інжестованого корпусу ми не можемо фактично підготувати або валідовати повноцінний реальний датасет. Формула Trust Score та результати наукових експериментів не змінюються.
