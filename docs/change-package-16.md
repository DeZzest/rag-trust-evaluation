# Пакет 16 — мінімальна прив'язка embedding-моделі та фіксація меж магістерської роботи

**Базова гілка:** `main` @ `b7a504e6058879537093c459fc2502f95cbce6c1` (merged PR #30, GitHub CI Success).
**Робоча гілка:** `feat/minimal-embedding-pin-thesis-scope`.

## Мета

Не розширювати безкінечно архітектуру. Закрити конкретну проблему: зараз окрема snapshot-колекція має лише назву за хешем корпусу й не зберігає навіть використаний embedding-model tag. Під час RAG-запиту різні моделі можуть мати однакову розмірність, але неузгоджені семантичні простори; збіг кількості та metadata фрагментів це не виявляє.

## Обсяг змін

1. Окремий чистий модуль `src/modules/vector/embedding.identity.ts`: перевіряє ім'я snapshot і nonempty `EMBEDDING_MODEL`, обчислює deterministic identity за `snapshotId + model tag + endpoint kind + similarity space`; не називає цей ідентифікатор хешем модельних ваг.
2. При `createExclusiveSnapshotCollection` додати до Chroma metadata модельний tag, snapshot ID та конфігурацію embedding. Уже існуючі колекції не змінювати.
3. `getExistingSnapshotCollection` перевірятиме ті самі metadata для **нового** snapshot endpoint; при відсутніх або невідповідних metadata — відмова до LLM. Старий legacy `/rag/query` не змінюється.
4. Синтетичні тести strict model-tag mismatch, tampered metadata, wrong snapshot ID, empty model; CI.
5. Затвердити **чернетку меж магістерської реалізації**: критерії приймання, 5 завершальних етапів, мінімальний benchmark, дії без доведеного ефекту й недосяжні промислові вимоги. Це не оформлене ТЗ до явного погодження користувача.

## Критерії

- Нова колекція має ідентифікатори corpus snapshot і embedding configuration, але без вигаданої версії/хеша ваг моделі.
- Новий read-only endpoint не приймає колекцію з невідомою/іншою model-tag.
- Snapshot/метадані legacy не змінюються; CLI з dry-run лишається read-only.
- Тести й TypeScript зелені. Жодних заяв про фактичну версію Ollama, якість векторів чи приріст Trust Score.
- Наступний пакет (№17) має завершувати програмні *наукові* вимоги: сформулювати й реалізувати мінімальний порівняльний метод оцінювання, після чого **заморозити функції** і перейти до реальних даних.

## Не виконуємо

Ні криптографічного доведення конкретних ваг LLM, ні нової бази даних, ні автоматичного OCR-рев'ю, ні інфраструктури розподілених запусків. `EMBEDDING_MODEL` — лише задекларований тег. Для наукової відтворюваності локально зберегти output `ollama show`, `ollama list`, версії сервісів, параметри й дату запуску.
