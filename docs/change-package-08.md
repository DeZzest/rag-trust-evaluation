# Пакет 8 — аудит репрезентативності корпусу та готовності черги

**Базовий commit:** `e5241707e4a28480f46f8997bd1a18de72bbae0d` (merged PR #21)  
**Гілка:** `feat/benchmark-corpus-readiness-audit`  
**Статус:** робочий план, без зміни Trust Score.

## Емпірична підстава

Переданий користувачем `ingested_corpus.jsonl` містить 1827 валідних записів і 26 різних ідентифікаторів документів; 1649 записів належать PDF-похідним документам за схемою `_pdf_<n>`, 571 фрагмент коротший за 30 символів, усі записи мають `year=2026` без підтвердження чинності джерела. Попередня черга для початкових 20 запитів містить лише 21 унікальний доказовий фрагмент при 82 призначеннях. Звідси ризик недостатнього покриття матеріалів і повторюваності випадків.

Це статистика наданого файлу, а не результат LLM-експериментів.

## План змін

1. `src/modules/evaluation/corpus.readiness.ts`: чистий валідатор вхідного JSONL і черги `annotation-queue/1` з підрахунком кількості/розмірів фрагментів, зразків PDF, років, дублікатів тексту, числа кандидатів на кейс, кількості унікальних кандидатних фрагментів, і кількості повторно використаних джерел. Звіряти SHA-256 точного JSONL зі snapshot черги.
2. `src/modules/evaluation/corpus.readiness.cli.ts`: локальна команда `npm run benchmark:audit -- <ingested.jsonl> <queue.json> [report.json]`; за замовчуванням лише агрегована статистика, без опублікування приватних текстів; опційний JSON-звіт через новий файл (`wx`).
3. `src/tests/corpus.readiness.checks.ts`: синтетичні перевірки коротких фрагментів, дублікатів, PDF-похідних документів, невірного SHA, відсутніх кандидатів та стабільності результатів.
4. `package.json`, `docs/benchmark-annotation-protocol.md`, `.gitignore`: команди, опис обмежень і захист згенерованого звіту.

## Критерії приймання

- Аудит не призначає вердикти і не викликає Ollama/ChromaDB.
- Вхідні JSONL помилки, відсутні обов'язкові метадані й розбіжність snapshot не ігноруються.
- Звіт явно показує концентрацію кандидатів і відсоток коротких фрагментів.
- Показники року розглядаються як **задекларовані метадані**, а не підтверджені дати чинності.
- Тести перевіряють підрахунки та захист від неконсистентних джерел.
- CI повинен пройти до Merge.

## Наступна окрема робота

Розширити протокол відбору кандидатних фрагментів із PDF та забезпечити різноманітність і тематичне покриття; затвердити розмір дослідницького корпусу й алгоритм незалежної перевірки його якості. Реальні експертні рішення та наукові показники не створюються цим пакетом.
