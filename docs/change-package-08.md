# Пакет 8 — контроль якості корпусу перед експертною розміткою

**Базовий commit:** `35fd3c9e75eb4af1cbb9372c89926587e8a27024`, `main`.  
**Гілка:** `feat/corpus-quality-audit`.  
**Примітка:** PR #21 на момент перевірки лишався відкритим, тому пакет 8 незалежний від нього та не змінює `package.json` і вихідний Trust Score.

## Підстава

Надані користувачем 1 827 JSONL-фрагментів із 26 документів (SHA-256 `68a25e82c514790f2545d91ce66dd4aab309ba789c9be72076bd08d8139cbc44`) мають спільний рік метаданих 2026, значну кількість коротких чанків і один плейсхолдер `No structured content extracted.`. Попередня черга кандидатних фрагментів для 20 запитів містить тільки 21 унікальний фрагмент на 82 включення, а запит q16 отримав лише плейсхолдер. Ці цифри — результати статичного аналізу **отриманого корпусу**, не метрики точності RAG.

## Зміни

1. Додати `corpus.quality.ts`: чистий аналізатор JSONL (кількість фрагментів, документів, коротких текстів, повторів і плейсхолдерів, розподіл років), опціональний аудит кандидата `annotation-queue/1` з контролем хешу корпусу, кількості повторів та кейсів лише з плейсхолдерами.
2. Додати `corpus.quality.cli.ts`: офлайнова діагностика з опціональним JSON звітом, без підключення ChromaDB/Ollama і без копіювання текстів документів у вихід.
3. Додати `corpus.quality.checks.ts` на **вигаданих** прикладах, з регресійними тестами malformed JSONL, повторів, непідтверджених років, невідповідного snapshot, недостатньої кількості джерел.
4. Підключити тести в CI без змін `package.json`, оскільки там очікує свого merge PR #21.
5. Не змінювати алгоритм відбору, не видаляти джерельні фрагменти, не призначати truth labels. Це лише інструмент вимірювання якості та виявлення ризиків.

## Критерії приймання

- Для незмінного JSONL — відтворюваний хеш та однакові агреговані показники.
- Чіткі сигнали про заглушки, короткі чанки, повтори, підозрілий загальний рік (без ствердження фактичної дати документа).
- Для черги вказати повторні використання джерел і випадки, де всі джерела є заглушками; невідповідність SHA-256 викликає явну помилку.
- Звіт не містить повних текстів університетських джерел і не включає приватних документів у Git.
- TypeScript і CI успішні. Жодні висновки про достовірність RAG-відповідей без наукового датасету не робити.
