# Пакет 3 — AUD-03: доказова перевірка тверджень (проєкт і план реалізації)

**База:** main @ `c72a431645715e82fefbb391c7e85d57eda6be58` (merged PR #16)  
**Гілка:** `feat/claim-grounding-evaluation`  
**Версія плану:** 0.1; **статус:** дозволений початковий пакет реалізації, не затверджене повне ТЗ.

## Проблема

`citation.extractor.ts` перевіряє індекси цитувань, але не підтвердження змісту фактологічних речень. Відповідь із цитуванням формально може бути неправдивою або суперечити документам. Поточні Trust Score й citation validity не слід називати підтвердженням істинності.

## Мінімальне технічне рішення

1. Додати незалежний модуль `src/modules/evaluation/claim.grounding.ts`, який приймає текст відповіді, retrieved-фрагменти і, за наявності, ідентифікатор моделі-судді.
2. Суддя пропонує атомарні твердження, вердикт `supported | contradicted | unsupported | uncertain`, і для підтримки/суперечності — мінімальну цитату з номером джерела.
3. Детермінована валідація: строгий JSON, структури полів, діапазону індексів джерел; перевірка, що цитата справді є підрядком відповідного retrieved-фрагмента (нормалізація пробілів допускається); відхилення відсутніх/підроблених доказів. Відповідність цитати твердженню залишається висновком LLM, а не криптографічним доказом семантичного entailment.
4. Додавати окремий висновок `claimGrounding` за явним опціональним параметром `includeClaimGrounding` у `POST /rag/query`. Новий модуль не входить до формули `trust.score.ts`; старі запити залишаються сумісними.
5. Відсутній або недоступний висновок судді повертається як `status: "unavailable"` із кодом помилки, а не як вигадане значення підтримки.
6. Написати чисті offline тести для парсера, прив'язки до реального джерела, невірного індексу, фальшивої цитати, порожнього списку тверджень і підрахунку агрегатів.
7. Додати CI перевірки до наявного `test:phase3`; окремо перевірити компіляцію й побудову інтерфейсу.

## Критерії приймання

- Атомарні твердження мають текст, машинний вердикт та доказ зі зв'язком `sourceIndex` → `RetrievedChunk`.
- `supported` або `contradicted` не з'являються у виході без наявного в retrieved-тексті доказового фрагмента; неправильні докази знижуються до `uncertain`.
- Суддя з невалідною JSON-схемою породжує помилку оцінювання, а не Trust Score.
- `POST /rag/query` без прапорця працює, як раніше, і Trust Score не змінюється.
- За відсутності retrieved-документів позначається статус `unavailable`.
- Офлайн unit-тести та GitHub Actions CI проходять; без запуску реальної Ollama не робимо висновків про фактичну точність.
- Для наукової валідації запланувати експертний gold dataset, precision/recall/F1 за класами та оцінку критичних хибнонегативних випадків.

## Межі пакета

- Не приписувати модулю гарантованого semantic entailment: перевірка цитат засвідчує лише наявність тексту.
- Не вводити нову формулу Trust Score, автоматичне блокування відповіді чи версійність нормативних документів — це окремі пакети після ТЗ і експериментальної валідації.
- Не змінювати `main` без Pull Request та успішного CI.
