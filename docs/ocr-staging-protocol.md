# Посторінкове OCR для сканованих університетських документів (пакет 10)

**Статус:** реалізовано формування *кандидатного* OCR-тексту. Це **не** затверджений нормативний корпус, не експертний gold і не доказ наукової точності RAG.

## Передумови

- Python 3.10+ (тільки стандартна бібліотека).
- Встановлені в системі та доступні через `PATH`: `pdfinfo`, `pdftotext`, `pdftoppm` (Poppler), `tesseract` (Tesseract 5+).
- `tesseract --list-langs` має містити **ukr** та **eng**.
- Файли `data/scrape_manifest.json` і PDF-кеш `data/raw_pdf/`. З раніше отриманого архіву `raw_pdf.zip` файли потрібно розпакувати так, щоб PDF були під `data/raw_pdf/`; можливі вкладені підпапки.
- Вхідні `data/university_corpus/` та `data/ingested_corpus.jsonl` **не змінюються**.

Для Windows установіть Tesseract із українським мовним пакетом і Poppler, додайте каталоги виконуваних файлів до `PATH`. Перевірте `python --version`, `pdfinfo -v` та `tesseract --list-langs`.

## Команда

```bash
npm run ocr:stage -- --manifest data/scrape_manifest.json --raw-pdf data/raw_pdf --output-dir data/ocr_staging
```

Для пробного проходу **однієї сторінки**:

```bash
npm run ocr:stage -- --document-id lute_regulations_2026_pdf_8 --max-pages 1
```

Результат буде у `data/ocr_staging/lute_regulations_2026_pdf_8.ocr.json` з `complete:false`; це лише smoke-test, не готовий документ. Для повної обробки вказаного документа при повторному запуску слід обрати **новий каталог результатів**: скрипт не перезаписує наявні файли.

Допустимі параметри: `--dpi 150..350` (типово 220), `--min-native-chars` (типово 40), `--min-ocr-chars` (типово 10). Пороги — **технічні евристики**, а не підтверджена міра якості OCR.

## Механізм

1. Отримати URL PDF із вихідного маніфесту та відтворити SHA-1-суфікс кешованого файла, як у `scrape.service.ts`; неоднозначні збіги заборонені.
2. Прочитати кількість сторінок `pdfinfo` та **сторінку за сторінкою** пробувати нативне витягування `pdftotext`.
3. Якщо текстового шару замало, отримати 220 DPI raster `pdftoppm` і TSV зі словами та raw confidences `tesseract -l ukr+eng`.
4. Відкинути тільки встановлені службові маркери `-- N of M --` і `No structured content extracted.`; зберегти інший текст, включно з короткими назвами. Порожній або надто короткий вміст має `reviewStatus:unreadable`.
5. Записати **не перевірений** JSON із `sourcePdfSha256`, `sourceUrl`, `declaredSourceYear`, кількістю сторінок, `complete`, `pageNumber`, `textSha256`, `extractionMethod`, `rawOcrMeanWordConfidence`, `reviewStatus`, повним кандидатним текстом.
6. Не передавати цей JSON до `ingest:corpus` і не підміняти ним вихідний TXT. Файли `data/ocr_staging/` ігноруються Git за замовчуванням.

`rawOcrMeanWordConfidence` — внутрішня статистика Tesseract, **не ймовірність істинності твердження, не OCR accuracy і не Trust Score**. Навіть якщо значення високе, порівняння зі сканом залишається обов'язковим.

## Контроль фактичної можливості наданих оригіналів

Поза CI у середовищі з інстальованими `ukr`/`eng` виконано **лише обмежений smoke-test** на першій сторінці трьох наданих PDF:

- `lute_regulations_2026_pdf_8`: сканована сторінка, OCR повернув ~553 алфавітно-цифрових символи, mean raw word confidence 87.4. Розпізнаються назва і дати документа, але є шум.
- `lute_academic_integrity_2026_pdf_1`: сканована сторінка, OCR повернув ~3331 символ, mean raw word confidence 89.1; потребує візуальної верифікації.
- `lute_regulations_2026_pdf_7`: нативний текстовий шар, ~1373 символи, OCR не потрібне.

Значення характеризують **окремі сторінки**, не всі 16 сканованих PDF. Повний запуск на всіх документах не виконано.

## Критерії приймання наступного етапу

Перед затвердженням нового `university_corpus_ocr_v1`:

- Перевірити всі OCR-сторінки, насамперед дати, номера наказів, статті, розділи, таблиці та заперечення.
- Вручну виправити помилки, зафіксувати відповідального, дату перевірки та зв'язок із `sourcePdfSha256` і `textSha256`.
- Визначити реальні редакції нормативних документів (поля `year=2026` недостатньо).
- Виконати **контрольований експорт** у новий каталог, зберегти старий корпус як baseline, отримати новий SHA-256 snapshot.
- Лише після перевірки — `ingest:corpus`, переіндексація, створення черги й еталонна розмітка.

Автоматичні юніт-тести запускати командою:

```bash
npm run test:ocr
```

Вони працюють на синтетичних прикладах і не потребують Poppler або Tesseract. OCR точність на реальних документах наразі **не виміряна**.
