# Пакет 7 — відтворюваний офлайновий звіт експерименту

**Дата:** 2026-11-18  
**Базова гілка:** `main` @ `35fd3c9e75eb4af1cbb9372c89926587e8a27024` (PR #20)  
**Робоча гілка:** `feat/benchmark-scoring-report`

## Мета

Надати інструмент для порівняння **явно узгоджених за caseId/claimId** вердиктів моделі з незалежним gold датасетом. Наявний `scoreClaimPredictions` обчислює класифікаційні метрики, але не має standalone CLI, контрольованого формату файлу прогнозів, перевірки однакового corpus snapshot і роздільного звіту `dev` / `test`.

## План внесення змін

1. Додати `src/modules/evaluation/benchmark.report.ts`: сувора схема `claim-predictions/1` з `datasetId`, `corpusSnapshotId`, `methodId`, `runId`, `predictions` і необов'язковим поясненням конфігурації; звірка з gold. Для чесної порівняльної таблиці неприйнятні невідомі/дубльовані/відсутні ID, а неприпустимі вердикти відхиляються.
2. Використати `scoreClaimPredictions` окремо для підмножин `dev` та `test`; якщо split порожній, повертати `null`, а не нульову оцінку. Відхиляти некоректні `datasetId` або `corpusSnapshotId`.
3. Додати CLI `npm run benchmark:score -- <gold.json> <predictions.json> [report.json]`, який відмовляється перезаписувати вихідні файли або вхідні файли, записує SHA-256 сирих вхідних файлів та протокол версії обчислень.
4. Додати лише **синтетичні** регресійні тести й команду `test:benchmark` (цей скрипт вже запускається CI).
5. Оновити `docs/benchmark-annotation-protocol.md`, `data/benchmark/README.md` і `.gitignore`.
6. **Не** змінювати Trust Score, не створювати експертні дані, не проводити експериментів із реальною Ollama до появи датасету.

## Критерії приймання

- Звіт розрізняє dev/test; чітко зазначає кількості випадків, тверджень та розподіл класів.
- Усі вхідні прогнози мають бути рівно один до одного вирівняні з `claimId`; відсутні/зайві/дубльовані прогнози є помилкою.
- Будь-яка невідповідність назви датасету або знімка корпусу відхиляється.
- Однакові вхідні файли дають однаковий обчислений результат та хеші.
- Вихідний репорт (як і всі gold/review файли) не потрапляє до публічного Git за замовчуванням.
- CI зелений; сам по собі цей факт **не доводить** точності методу на реальному корпусі.

## Не включено в цей пакет

- Зіставлення довільної LLM-декомпозиції відповіді з вручну розміченими `claimId`.
- Генерація прогнозів у реальному оточенні Ollama/ChromaDB та калібрування Trust Score.
- Незалежна підтверджена якість експертів, статистична потужність або перевага над baseline.
