# Пакет 10 — посторінкове українськомовне OCR та збереження походження джерел

**Базова гілка:** `main` @ `74b26522cb30c7fccec90a0a4456080d65ca594a` (PR #24)  
**Робоча гілка:** `feat/ocr-page-staging`  
**Тип зміни:** підготовка даних для майбутніх досліджень, **без** модифікації Trust Score.

## Підстава

Фактичний аудит наданих архівів: 21 PDF, 340 сторінок; 16 PDF та 297 сторінок фактично скановані, 301 сторінка без витягуваного тексту. PR #24 не допускає індексацію службових рядків, але не відновлює документальний текст.

## План до зміни коду

1. Створити `scripts/ocr_stage.py` (Python standard library + зовнішні `pdfinfo`, `pdftotext`, `pdftoppm`, `tesseract`) з читанням **локального** `data/scrape_manifest.json` та PDF cache `data/raw_pdf/` без мережевих викликів.
2. Однозначно знаходити локальний PDF за тим самим SHA-1-суфіксом URL, що використовується скрапером. Помилка, якщо файл відсутній або неоднозначний.
3. Обробляти PDF **посторінково**: використовувати наявний текстовий шар, а при його недостатності — OCR `ukr+eng`; видаляти лише ідентифіковані службові рядки.
4. Записувати окремі `data/ocr_staging/<documentId>.ocr.json` із текстом і SHA-256 кожної сторінки, номером сторінки, режимом отримання тексту, сирим word-confidence Tesseract, статусом `needs_manual_review` або `unreadable`, хешем PDF, оригінальним URL, кількістю сторінок і повнотою обробки.
5. Дозволити запуск обраного документа або частини сторінок для тестування, але неповний результат відзначати `complete:false`. Не перезаписувати наявні файли.
6. Додати лише офлайнові unit-тести без реальних PDF до CI; підтвердити можливість реального OCR на кількох сторінках наданого архіву **окремо від** CI.
7. Документувати встановлення OCR-залежностей (українська мова), перевірку сторінок, редакційність джерел, правила нового corpus snapshot і перехід від `ocr_staging` до експертно підтвердженого корпусу в наступному пакеті.

## Критерії приймання

- За однакових PDF і налаштувань зберігаються стабільні SHA-256 джерел та тексту сторінок; дата генерації не використовується як дата нормативної чинності.
- Сканований PDF генерує **кандидатний OCR-текст**, який не потрапляє автоматично в `university_corpus` або ChromaDB.
- Сторінки без змісту позначаються `unreadable`; жодних вигаданих текстових заглушок.
- `ukr` та `eng` мають бути встановлені в Tesseract; відсутність залежностей спричиняє явну помилку.
- Вхідні PDF/TXT/JSONL залишаються незмінними.
- Синтетичні unit-тести та GitHub CI проходять; продемонстровано реальний OCR на обмеженій вибірці без проголошення повноти чи точності.
- У `main` зміни потрапляють тільки після review і Merge PR.

## Межі

Пакет **не** доводить точності OCR, не перевіряє чинність нормативних документів і не завершує підготовку експертного gold dataset. Наступний пакет — перевірка/затвердження OCR-сторінок і контрольований експорт нової версії корпусу для `ingest:corpus` із page provenance.
