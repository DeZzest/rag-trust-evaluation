## Пакет 1 — AUD-02: коректність Recall@k

**Проблема.** Наявна функція `calculateRetrievalMetrics` порівнює список retrieved-фрагментів з переліком унікальних релевантних документів. Два фрагменти одного документа зараховуються двічі до чисельника `recallAtK`, тому значення може перевищити 1.

**Зміни.**
- `src/modules/evaluation/retrieval.metrics.ts`: рахувати кількість **унікальних знайдених релевантних ідентифікаторів документів** у чисельнику `recallAtK`.
- `src/tests/phase3.checks.ts`: додати тести дублікатів чанків, неповного охоплення та порожнього списку еталонних документів.
- Не змінювати формулу `precisionAtK` в цьому пакеті: вона залишиться часткою релевантних retrieved-фрагментів. Розмежування chunk-level та document-level Precision@k винести в окрему вимогу ТЗ.

**Критерії приймання.**
- `recallAtK` завжди в діапазоні [0, 1] за коректних вхідних ідентифікаторів.
- Два або більше чанків одного релевантного документа враховуються в recall лише один раз.
- Якщо знайдено лише один з двох релевантних документів, recall дорівнює 0.5, незалежно від кількості його чанків.
- Початкові тести без дублікатів продовжують відповідати очікуваним значенням.

**Межі перевірки.** Статичний аналіз або автономні тести не замінюють наскрізного запуску із ChromaDB та Ollama; цей стан фіксується окремо.
