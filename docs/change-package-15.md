# Пакет 15 — повний аудит вмісту ChromaDB відносно corpus snapshot

**База:** `main` @ `bab92eb47fe5a6f87234799bfe070a02c39f2241`, Merge PR #29, CI Success.  
**Гілка:** `feat/snapshot-chroma-integrity-audit`.

## Фактичний ризик
- Пакет 13 після запису перевіряє лише загальну кількість Chroma-записів.
- Пакет 14 також перевіряє count і походження *повернутих* фрагментів до виклику LLM.
- Збіг count або selected metadata **не підтверджує** еквівалентності *всієї* колекції вхідному JSONL. Не виявляються зміна тексту, заміна іншого chunk ID чи неправильні дані в записах, які retrieval не повернув.
- Поточна назва колекції не фіксує `EMBEDDING_MODEL`/version; неможливо криптографічно довести походження embedding-векторів лише з їхньої розмірності.

## План
1. В `chroma.service.ts` додати read-only отримання записів Chroma v2 POST `/collections/{id}/get` із `offset`/`limit` і `include: ["documents","metadatas","embeddings"]`. Відхиляти некоректну форму відповіді, а не приховано підставляти порожні рядки.
2. Додати `snapshot.audit.ts`: використати наявний `loadVerifiedSnapshotIndexPlan` перед мережевими викликами; читати **всю** існуючу колекцію сторінками (максимум 50 елементів), порівняти рівно один до одного ID/точний текст/всі metadata, перевірити валідність і сталу розмірність embedding-векторів, загальну кількість до/після. Жодних add/delete/create/update.
3. Додати CLI `corpus:audit-index -- --snapshot-dir <path> --expected-snapshot sha256:<64hex>`, безпечний тільки для existing-only snapshot collection. На помилці nonzero exit, без часткового «успіху».
4. Додати синтетичні offline регресійні тести на missing/duplicate/foreign ID, змінений текст, metadata, NaN/infinite/різні довжини embedding, count mismatch, невдалу HTTP-відповідь і read-only сценарій.
5. Додати CI-тести, протокол і журнал ручної конфігурації embedding-моделі; **не** змінювати індексатор, RAG API або Trust Score у цьому пакеті.

## Критерії приймання
- Ізольована колекція відповідає snapshot за всім набором ID, текстів і метаданих, а не лише за кількістю.
- Читання виключно read-only; відсутня або невідповідна колекція спричиняє помилку.
- Всі збережені embeddings присутні, скінченні, однакової додатної розмірності; їхнє походження від конкретної моделі **не виводиться** з цих властивостей.
- Пошкоджений snapshot відхиляється до будь-якого звернення до ChromaDB.
- Тести CI зелені на синтетичних даних; реальний інтеграційний запуск ще потрібно зробити локально після OCR та створення reviewed corpus.

## Наступний пакет
Зв'язати модель/версію або digest, конфігурацію ембеддера і corpus snapshot в окремій experiment identity. Упровадити reject-on-mismatch до query та індексації з тестами; не приписувати попереднім колекціям недоведене походження векторів.
